# ADR 0006：附件路径与命名策略

- 状态：已接受
- 日期：2026-10-20
- 决策者：项目维护者
- 相关文档：[附件管理](../features/attachments.md)、[数据与迁移](../data-and-migrations.md)

## 背景

附件管理需要同时满足：

- 粘贴图片时，保存到配置的附件根目录，并保留笔记的目录结构。
- 目录不存在时自动创建。
- 每次粘贴允许用户重命名文件。
- 上传文件时，在光标处插入引用链接。
- 文件名可追溯到来源笔记，同时避免同名覆盖。
- 生成的链接遵循用户已有的 Obsidian 链接偏好。

路径和命名一旦发布，就会成为用户文件系统的一部分；后续修改会影响已有附件和链接。因此需要明确记录策略和后果。

## 决策

### 路径

```text
targetDir = assetsRoot + "/" + dirname(note.path)
```

- `assetsRoot` 默认 `assets`，是 Vault 相对路径。
- 输入 `/assets` 会规范化为 `assets`；拒绝绝对路径、盘符路径和 `..`。
- 保留笔记完整目录层级；根目录笔记直接保存到 `assetsRoot`。
- 目录逐级创建；目标路径是文件而不是目录时报错。

### 文件名

- 粘贴图片默认模板：`{note}-{suffix}`；上传文件默认模板：`{suffix}`。
- `{note}`：笔记文件名，不含 `.md`，经过清洗。
- `{suffix}`：
  - 粘贴图片：13 位毫秒时间戳；
  - 上传文件：原文件名（清洗后），不含扩展名。
- `{timestamp}`：本地时间 `YYYYMMDD-HHmmss`。
- 扩展名自动追加；模板不允许包含路径分隔符。
- 上传默认不添加笔记前缀，保留原文件名。
- 冲突时追加 `-1`、`-2`；重命名对话框先提示冲突。

### 粘贴交互

- 每次粘贴图片都逐张弹出重命名对话框。
- 取消任意一张则整批中止；不创建目录、不保存文件、不插入链接。
- 重命名只改基础文件名，扩展名固定。
- 多张图片按顺序命名，然后统一保存并插入多行链接。

### 上传交互

- 通过命令触发，由用户绑定快捷键；不预设默认热键。
- 文件选择器支持多选。
- 上传不弹重命名对话框；文件名由上传模板决定，默认保留原文件名，之后可用文件管理器重命名。

### 链接

- 使用 `FileManager.generateMarkdownLink(file, note.path)`，尊重用户的 wiki / Markdown 和相对路径偏好。
- 图片默认加 `!` 变为嵌入；可通过设置关闭。
- 生成失败时回退为 `[[path]]`。

### 默认状态

首个核心特性默认启用，开箱即用；用户可在设置页关闭，关闭后恢复 Obsidian 默认粘贴行为。

## 结果

### 正面

- 附件与笔记的目录归属清晰。
- 不同目录下的同名笔记不会互相覆盖。
- 粘贴前即可命名，取消不产生孤儿文件。
- 粘贴文件名可追溯到笔记；上传文件默认保留原名，减少无意义前缀。
- 链接形态与用户 Obsidian 设置一致。
- 上传命令可绑定任意快捷键，避免冲突。

### 负面 / 代价

- 移动或重命名笔记不会自动迁移已有附件。
- 修改 `assetsRoot` 或模板不会迁移已有文件。
- 每次粘贴都会打断编辑，这是用户明确选择的交互。
- 粘贴文件名包含 13 位毫秒时间戳，较长；同一毫秒内可能需要重命名或 `-1`。
- 粘贴和上传各有一个模板，设置项增加。
- 目录层级较深时路径较长；极端情况下可能触发操作系统路径长度限制。
- 多图逐张弹窗在图片很多时较慢。
- 上传文件不在保存前命名；需要改名时要使用文件管理器。
- 撤销链接不会删除已保存文件。

## 备选方案

### 所有附件平铺在 `assets/`

简单，但不同目录的同名笔记容易冲突，且附件与笔记的归属不清晰。

### 使用 Obsidian 默认附件目录

`FileManager.getAvailablePathForAttachment` 可以遵循 Obsidian 设置，但无法实现“按笔记目录结构 + 自定义模板 + 每张图片重命名”的组合需求。

### 按日期分目录

`assets/2026/10/20/...` 便于按时间归档，但丢失笔记归属，移动笔记时更难追踪。

### 自动使用随机名，不弹窗

交互最轻，但不满足“允许用户 rename”的要求，用户事后仍需整理文件名。当前改用毫秒时间戳，便于排序且减少随机感。

### 粘贴和上传共用一个模板

设置更少，但上传会带上笔记前缀，无法同时满足“上传保留原名”和“粘贴可追溯”。当前选择拆成两个模板。

### 上传也弹重命名

一致性更好，但上传文件本身已有名称，额外弹窗会增加一次不必要的交互。当前选择保持上传流程快速。

## 重新评估条件

- 用户需要笔记重命名/移动时自动迁移附件；
- 用户需要扁平附件目录或按日期归档；
- 上传也需要保存前重命名；
- 需要按笔记/文件夹覆盖 `assetsRoot` 或模板；
- 操作系统路径长度或同步工具对深层目录造成实际限制；
- 用户希望恢复默认关闭，或希望提供“连续粘贴不弹窗”模式。
