# ADR 0007：整篇渲染后按 DOM 分区生成演示页

- 状态：已接受
- 日期：2026-10-29
- 决策者：项目维护者
- 相关文档：[Markdown 演示](../features/slides.md)、[架构设计](../architecture.md)

## 背景

“Markdown 演示”需要把任意笔记转换成铺满屏幕的全屏演示页，且：

- 不要求用户添加 `---`，按 H1/H2 标题层级自动分页。
- H1 单独成为主题页；H2 成为正文页；页眉为可选能力，默认关闭，开启后显示 `H1-H2`。
- 代码块、公式、Mermaid、Callout、图片、嵌入、表格与 Obsidian 阅读视图一致。
- 不引入运行时依赖，不修改 `FeatureContext` / `PluginHost`。

现有社区插件中，Podium 能做到零适配自动分页，但没有 H1/H2 层级主题页和页眉；Paperish Presentation 有 H1 标题页和祖先标题条，但不是铺满屏幕的 PPT 画布，也没有本项目需要的设置和生命周期。Marp / Advanced Slides / Slides Extended 都要求特定分隔语法，与“零适配”冲突。

## 决策

### 渲染

使用 `MarkdownRenderer.render` 把整篇笔记渲染到一个隐藏容器，然后按**渲染后的顶层 DOM 子元素**分区：

- `H1`–`H6` 是按层级分页的依据；
- `HR` 是可选的手动分页；
- 其他顶层元素归入当前正文页；
- 原始 DOM 节点被移动到铺满屏幕的页面，保留 Obsidian 的渲染结果和事件监听。

`planSlides` 是纯函数，接收 `Block[]`（标题层级、文本、元素引用），输出主题页/正文页计划，便于在 Node 中测试。

### 页面

- H1 主题页：只包含 H1 元素。
- H2 正文页：H2 作为页标题，后续块为正文；页眉可选，默认关闭。
- H3–H6：留在当前正文页内。
- H1 后、第一个 H2 前的内容：单独正文页；开启页眉时页眉只有 H1。
- 首个标题前的内容：引言正文页；开启页眉时使用 frontmatter `title` 或文件名。

### 展示

- 使用全屏 `Modal`，不注册自定义 `ItemView`；打开演示时在用户手势内请求浏览器全屏，失败时保留铺满窗口的 Modal。
- 舞台根据自身宽度设置 `--aio-slides-unit`，所有字号/间距按比例缩放。
- 内容超出时按 5% 步进缩放到 50%，仍超出则页内滚动。
- 不实现 `.pptx` / PDF 导出。

## 结果

### 正面

- 不需要自己实现 Markdown 解析器，围栏代码、公式、HTML、Callout 等边界由 Obsidian 处理。
- 双链、嵌入、Mermaid、图片、脚注等与阅读视图一致。
- 分页规则是纯函数，测试成本低。
- 不新增依赖，不修改核心架构。
- 全屏 Modal 的生命周期简单，关闭特性时可以确定地清理。

### 负面 / 代价

- 分页依赖渲染后的顶层 DOM；把标题包在 `<div>` 里的 HTML 块不会分页。
- 演示是快照，编辑后需要重新打开。
- 脚注跟随整篇渲染，通常落在最后一页。
- 第三方插件在渲染完成后异步添加的顶层节点不保证重新分页。
- 长内容只缩放/滚动，不做自动续页。
- Modal 不支持并排预览、独立投影窗口或恢复工作区状态。
- 不生成 `.pptx`，不能直接交付 PowerPoint 文件。

## 备选方案

### 逐页调用 `MarkdownRenderer.render`

按源码行范围切分 Markdown，再逐页渲染。分页更直接，也能天然支持“从光标处开始”，但需要可靠的 Markdown 扫描器，并会破坏跨页脚注、同笔记嵌入和部分链接解析。

### 使用 reveal.js / Slides Extended

可以获得成熟的转场、垂直幻灯片和主题生态，但需要引入 reveal.js 运行时，且默认要求 `---` / `--` 语法；与本特性的“零适配”目标冲突。

### 使用 Marp

Marp 支持 `headingDivider` 和 PPTX 导出，但分页语义是“每个标题一页”，没有 H1 主题页 + H2 正文页 + `H1-H2` 页眉，也没有本项目需要的生命周期和设置。PPTX 导出还依赖 Chrome。

### 直接依赖 Paperish Presentation

它能做到 H1 标题页 + H2 分页 + 祖先标题条，最接近本需求；但页眉在底部、分隔符固定、不是铺满屏幕的画布，且无法按本项目的方式管理设置、命令和清理。适合作为零代码替代方案，不适合作为内部实现依赖。

### 生成临时 Markdown 交给核心 Slides

可以把笔记预处理成带 `---` 的临时文件，但会污染 Vault、破坏相对链接/嵌入的 sourcePath，且无法控制画布、页眉和缩放。

## 重新评估条件

- 用户需要 `.pptx` / PDF 交付，需要另立导出 ADR。
- 用户经常写超长 H2 内容，需要块级自动续页。
- 需要并排预览、独立投影窗口或可恢复的演示标签页，应评估 `ItemView` 与核心视图注册包装。
- DOM 分区在真实第三方插件组合下出现无法接受的分页错误，应改为源码解析 + 逐页渲染。
- 需要可配置标题层级、演讲者备注或缩略图总览时，重新评估页面模型。
