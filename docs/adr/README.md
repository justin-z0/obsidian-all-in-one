# ADR 索引

本目录记录影响多个模块、难以回退或带有显著代价的架构决策。

## 什么时候写 ADR

- 决策影响多个模块或长期维护方式；
- 决策引入版本限制、依赖或显著样板；
- 有至少一个值得记录的备选方案；
- 未来维护者会问“为什么不是另一种做法”。

普通 bug 修复、局部重构和样式调整不需要 ADR。

## 状态

| 状态 | 含义 |
|---|---|
| 提议 | 正在讨论，尚未采用 |
| 已接受 | 当前方案，代码和文档应遵循 |
| 已废弃 | 不再使用，但保留历史 |
| 已取代 | 被新的 ADR 取代，需链接新 ADR |
